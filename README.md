# CryptoScope AI

منصة ويب احترافية باللغة العربية (RTL) لتحليل العملات الرقمية بذكاء متعدد المؤشرات: الاتجاه، الزخم، السيولة، والمخاطر، مع تقارير مفصّلة وتقييم احتمالي ومستوى ثقة وسيناريوهات.

> ⚠️ **تنبيه مهم:** جميع النتائج تقييم آلي وإشارات تحليلية لأغراض تعليمية ومعلوماتية فقط، وليست نصيحة مالية أو استشارة استثمارية مرخّصة.

## التقنيات

- **Next.js 15** (App Router) + **TypeScript** + **React 19**
- **Tailwind CSS** + مكونات بأسلوب **shadcn/ui** (Radix UI)
- **Lightweight Charts** للرسوم التفاعلية و**Recharts** للرسوم المختصرة
- **PostgreSQL** + **Prisma ORM**
- **NextAuth** (Credentials + Google اختياري) مع bcrypt وجلسات JWT آمنة
- **Zod** للتحقق من البيانات (برسائل عربية)
- **TanStack Query** لجلب البيانات وتخزينها مؤقتًا
- **Vitest** للاختبارات
- الوضع الداكن افتراضيًا، تصميم متجاوب، وبنية جاهزة لإضافة الإنجليزية لاحقًا

## التثبيت

المتطلبات: **Node.js 20.9+** و**PostgreSQL 14+**.

```bash
git clone <repo-url> cryptoscope-ai
cd cryptoscope-ai
cp .env.example .env        # ثم عدّل القيم (انظر الأقسام التالية)
npm install
npx prisma migrate dev
npm run dev
```

افتح: <http://localhost:3000>

## إعداد قاعدة البيانات

1. أنشئ مستخدمًا وقاعدة بيانات PostgreSQL، أو شغّل واحدة عبر Docker:

   ```bash
   docker run -d --name cryptoscope-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:16
   ```

2. ضع رابط الاتصال في `.env`:

   ```env
   DATABASE_URL="postgresql://postgres:postgres@localhost:5432/cryptoscope?schema=public"
   ```

3. طبّق الترحيلات:

   ```bash
   npx prisma migrate dev
   ```

   إذا لم تكن قاعدة البيانات موجودة، يُنشئها Prisma ويشغّل البذر تلقائيًا (إضافة قائمة الأصول). لتشغيل البذر يدويًا: `npm run db:seed`.
   لاستعراض البيانات: `npm run db:studio`.

## إضافة مفاتيح API

كل المفاتيح **اختيارية** وتبقى على الخادم فقط (لا توجد أي متغيرات بالبادئة `NEXT_PUBLIC_`). المصادر المجانية تعمل دون مفاتيح بحدود طلبات أقل.

| المتغير | الاستخدام |
|---|---|
| `NEXTAUTH_SECRET` | **مطلوب** — ولّده: `openssl rand -base64 32` |
| `NEXTAUTH_URL` | عنوان التطبيق (مثلًا `http://localhost:3000`) |
| `COINGECKO_API_KEY` + `COINGECKO_API_PLAN` | `demo` (مجاني) أو `pro`. مفتاح **Pro** يتيح تاريخ إجمالي السوق لحساب BTC.D وUSDT.D وTOTAL تاريخيًا |
| `COINMARKETCAP_API_KEY` | مصدر احتياطي للأسعار وبيانات السوق العامة |
| `BINANCE_API_KEY` / `BINANCE_API_SECRET` | غير مطلوبة لبيانات الشموع العامة؛ لا يُستخدم السر لأن المنصة لا تنفذ أوامر تداول |
| `BINANCE_BASE_URL` | الافتراضي `https://data-api.binance.vision` (بيانات السوق العامة) |
| `TRADINGVIEW_API_KEY` | فقط لتكامل رسمي مرخّص؛ بدونه تُعرض رسوم محلية — لا يوجد أي Scraping |
| `CRYPTOPANIC_API_KEY` | أخبار اختيارية (تؤثر بوزن صغير في فئة الأخبار) |
| `CRON_SECRET` | حماية مسار المهام المجدولة |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | تفعيل الدخول عبر Google (Redirect URI: `<NEXTAUTH_URL>/api/auth/callback/google`) |
| `SMTP_URL` / `EMAIL_FROM` | إرسال رسائل التأكيد والاستعادة. بدون SMTP تُطبع الروابط في سجل الخادم أثناء التطوير |
| `REQUIRE_EMAIL_VERIFICATION` | `true` (افتراضي) يشترط تأكيد البريد قبل الدخول |
| `DATA_MODE` | `live` أو `mock` |

**ترتيب المصادر (مع بدائل احتياطية تلقائية):**

- الأسعار والقيم السوقية: CoinGecko ← CoinMarketCap
- الشموع OHLCV: Binance ← CoinGecko (شموع مجمّعة من نقاط سعرية، مع وسمها وخفض جودة البيانات)
- BTC.D / USDT.D / TOTAL / TOTAL2 / TOTAL3: محسوبة من بيانات السوق العامة؛ وتاريخها من CoinGecko Pro أو من اللقطات المحفوظة في قاعدة البيانات
- الخوف والطمع: alternative.me

## وضع البيانات التجريبية Mock

للتطوير المحلي دون اتصال بمزودي البيانات:

```env
DATA_MODE="mock"
```

- يظهر أعلى التطبيق شريط: **«وضع تجريبي - البيانات المعروضة غير لحظية»**.
- البيانات مولّدة حتميًا (نفس الرمز ← نفس السلسلة) وموسومة دائمًا `isMock=true`، وتظهر التقارير بشارة **«بيانات تجريبية»**.
- **يُعطَّل وضع Mock تلقائيًا في الإنتاج** (`NODE_ENV=production`) ويُستخدم المزود الحي، ولا تظهر التقارير التجريبية في قوائم الإنتاج.
- لا تُحفظ الشموع التجريبية في جدول OHLCV ولا تدخل في لقطات السوق.

## المهام المجدولة

مسار `GET|POST /api/cron/snapshot` (محمي بـ `Authorization: Bearer $CRON_SECRET`) يقوم بـ:

1. حفظ لقطة لبيانات السوق العامة — تُبنى منها سلاسل BTC.D وUSDT.D وTOTAL التاريخية عند عدم توفر مفتاح CoinGecko Pro.
2. تقييم تنبيهات المستخدمين مع احترام فترة التهدئة.
3. حذف سجلات مزودي البيانات الأقدم من 14 يومًا.

يُنصح بتشغيله كل 15 دقيقة، مثلًا عبر cron:

```bash
*/15 * * * * curl -s -H "Authorization: Bearer $CRON_SECRET" https://your-domain.com/api/cron/snapshot
```

أو عبر Vercel Cron (أضف `vercel.json` بمسار المهمة، وضع `CRON_SECRET` في متغيرات المشروع؛ Vercel يرسل الترويسة تلقائيًا).

## نشر المشروع

### Vercel + PostgreSQL مُدار (Neon / Supabase / RDS)

1. أنشئ قاعدة PostgreSQL واحصل على `DATABASE_URL`.
2. اربط المستودع بـ Vercel وأضف متغيرات البيئة (على الأقل `DATABASE_URL`، `NEXTAUTH_SECRET`، `NEXTAUTH_URL`، `CRON_SECRET`، و`DATA_MODE=live`).
3. أمر البناء: `npm run build`. طبّق الترحيلات قبل أول تشغيل (أو ضمن خطوة النشر):

   ```bash
   npx prisma migrate deploy
   ```

4. أضف مهمة مجدولة لمسار `/api/cron/snapshot`.

### خادم خاص (VPS) أو Docker

```bash
npm ci
npx prisma migrate deploy
npm run build
NODE_ENV=production npm start   # خلف وكيل عكسي مثل Nginx مع HTTPS
```

**ملاحظات الإنتاج:**

- استخدم HTTPS دائمًا (ملفات تعريف الارتباط Secure تلقائيًا).
- محدد المعدل والذاكرة المؤقتة في الذاكرة مناسبان لخادم واحد؛ عند التشغيل على عدة خوادم استبدلهما بـ Redis عبر نفس الواجهات (`lib/security/rate-limit.ts` و`lib/providers/cache.ts`).
- اضبط `SMTP_URL` لإرسال رسائل التأكيد والاستعادة.

## النسخة الثابتة على GitHub Pages

GitHub Pages يستضيف ملفات ثابتة فقط (بدون خادم Node.js ولا قاعدة بيانات)، لذلك يوفّر المشروع **نسخة ثابتة** تُبنى من نفس الكود:

| الميزة | نسخة الخادم | النسخة الثابتة (Pages) |
|---|---|---|
| لوحة التحكم والتقارير والرسوم | ✓ | ✓ — التحليل يعمل داخل المتصفح |
| مصادر البيانات | من الخادم (مع مفاتيح اختيارية) | مباشرة من المتصفح عبر الواجهات العامة: CoinGecko وBinance وalternative.me (دون مفاتيح) |
| حفظ التقارير | PostgreSQL | Local Storage في متصفح المستخدم (آخر 25 تقريرًا) |
| المفضلة | الحساب أو المتصفح | المتصفح |
| تسجيل الدخول والتنبيهات | ✓ | ✗ (تظهر رسالة توضيحية) |
| تاريخ BTC.D وUSDT.D | CoinGecko Pro أو لقطات قاعدة البيانات | لقطات تُجمع في المتصفح مع الزيارات |

### التفعيل (مرة واحدة)

1. في المستودع: **Settings → Pages → Build and deployment → Source** واختر **GitHub Actions** (بدل *Deploy from a branch*).
2. أي دفع (push) إلى الفرع الافتراضي يشغّل سير العمل `.github/workflows/deploy-pages.yml`: يثبّت الحزم، يشغّل الاختبارات، يبني النسخة الثابتة، ثم ينشرها.
3. يمكن تشغيله يدويًا من تبويب **Actions → Deploy to GitHub Pages → Run workflow**.

الرابط: `https://<username>.github.io/<repo>/`

### البناء محليًا

```bash
NEXT_PUBLIC_BASE_PATH=/Ai_crypto npm run build:pages   # الناتج في out/
```

يقوم السكربت `scripts/build-pages.mjs` بنقل مسارات الـ API والوسيط مؤقتًا (لأن التصدير الثابت لا يدعمها) ثم يعيدها تلقائيًا، ويضيف `.nojekyll`.

> ملاحظة: مزودو البيانات المجانيون لديهم حدود طلبات لكل مستخدم؛ عند تجاوزها تظهر رسالة عربية بالانتظار دقيقة. للاستخدام الكثيف أو للحسابات والتنبيهات انشر نسخة الخادم (Vercel + PostgreSQL).

## نظام التحليل والتقييم

1. **جلب البيانات** لكل الأطر الزمنية (15 دقيقة، ساعة، 4 ساعات، يومي، أسبوعي) + السوق العام + الخوف والطمع + الأخبار (اختياري). فشل أي مصدر لا يوقف التقرير بل يخفض جودة البيانات.
2. **التحقق من الجودة**: عدد الشموع، حداثتها، البيانات القديمة من الذاكرة المؤقتة، الشموع المجمّعة، توفر بيانات السوق.
3. **حساب المؤشرات** على الشموع المكتملة فقط، وتحويل كل مؤشر إلى إشارة من −1 إلى +1 مع شرح عربي.
4. **التجميع** في فئات بأوزان قابلة للتعديل في `src/config/scoring.ts`:

   | الفئة | الوزن |
   |---|---|
   | الاتجاه العام | 20% |
   | الزخم | 15% |
   | المتوسطات المتحركة | 15% |
   | الحجم والسيولة | 15% |
   | الدعم والمقاومة | 10% |
   | التقلب والمخاطر | 10% |
   | السوق العام وBTC.D وUSDT.D | 10% |
   | جودة البيانات والأخبار | 5% |

   الفئات غير المتاحة تُستبعد ويُعاد تطبيع الأوزان. أوزان الأطر الزمنية تتغير حسب الأفق (قصير/متوسط/طويل).
5. **الدرجة الخام** (0–100، حيث 50 = محايد) ← **الدرجة المعدلة** = 50 + (الخام − 50) × عامل جودة البيانات.
6. **الثقة** = جودة البيانات + توافق الإشارات + توافق الأطر الزمنية + التغطية (حد أقصى 95%).
7. **حواجز الأمان**:
   - تضارب الإشارات أو الأطر الزمنية المؤثرة ← «محايد / انتظار».
   - بيانات ناقصة ← «محايد / انتظار» وثقة ≤ 30%.
   - ثقة < 40% ← تحييد الإشارة.
   - «شراء محتمل» يتطلب ثقة ≥ 60%، و«بيع محتمل» يتطلب اتجاهًا طويلًا هابطًا مع ADX ≥ 25 وثقة ≥ 60%.
   - المؤشرات السوقية (BTC.D، USDT.D، TOTAL، ETH/BTC) والعملات المستقرة ← «مؤشر سوقي — لا توصية مباشرة».

**نطاقات الإشارة:** 80–100 إيجابي قوي · 65–79 إيجابي بحذر · 45–64 محايد · 30–44 سلبي بحذر · 0–29 سلبي قوي.

**قواعد مختارة:** فوق EMA 200 مع ميل إيجابي = إيجابي؛ EMA 20 فوق EMA 50 = إيجابي متوسط؛ RSI بين 45 و65 مع اتجاه صاعد = إيجابي؛ RSI فوق 75 = تحذير وليس بيعًا؛ RSI تحت 25 = احتمال ارتداد وليس شراءً؛ MACD فوق الإشارة مع هيستوجرام إيجابي = إيجابي؛ صعود السعر مع انخفاض الحجم = تحذير؛ ارتفاع USDT.D بقوة = تحذير؛ BTC.D وUSDT.D يرتفعان معًا = Risk-Off محتمل؛ BTC.D ينخفض والسوق يرتفع = توسع السيولة للبديلة.

**حساب الهيمنة:** `BTC.D = BTC Market Cap / Total Market Cap × 100` و`USDT.D = USDT Market Cap / Total Market Cap × 100`، مع عرض مصدر الحساب وتاريخه. اختلاف تعريف "إجمالي السوق" بين المزودين قد ينتج فروقًا.

**المستويات:** مشتقة فقط من تجميع القمم والقيعان الحقيقية؛ يظهر «غير متاح» عند نقص البيانات. مستوى الإبطال = الدعم الأول − ATR(14).

## الأمان

- التحقق من **جميع المدخلات** بـ Zod (رموز، معرفات، أحجام صفحات، أجسام الطلبات).
- **SQL Injection**: كل الاستعلامات عبر Prisma (استعلامات مُعلَّمة)، دون SQL نصي.
- **XSS**: React يرمّز المخرجات، ولا يُستخدم `dangerouslySetInnerHTML`؛ مع سياسة CSP صارمة وترويسات أمان (`next.config.ts`) وتنظيف إضافي للنصوص.
- **مفاتيح API** على الخادم فقط؛ كل طلبات المزودين تتم من الخادم.
- **كلمات المرور**: bcrypt (cost 12)، وسياسة كلمات مرور قوية، ورموز التأكيد/الاستعادة تُخزَّن كتجزئة SHA-256 فقط مع صلاحية محدودة.
- **الجلسات**: JWT في ملفات تعريف ارتباط HttpOnly / SameSite=Lax / Secure في الإنتاج.
- **CSRF**: NextAuth يحمي مساراته، والمسارات المعدِّلة الأخرى تتحقق من تطابق Origin مع المضيف.
- **الصلاحيات**: الوسيط يحمي `/alerts` و`/api/alerts`، والتقارير الخاصة لا تظهر إلا لمالكها (404 دون كشف وجودها).
- **Rate Limiting** على إنشاء التقارير وتسجيل الدخول والتسجيل والاستعادة.
- **السجلات** تُحجب منها الأسرار تلقائيًا، وسجلات المزودين تخزن المسار فقط دون معاملات الاستعلام.

interface MarketDataProvider {
